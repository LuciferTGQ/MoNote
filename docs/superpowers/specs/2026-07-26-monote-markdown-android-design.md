# 墨笺（MoNote）Markdown Android MVP 设计规格

- 日期：2026-07-26
- 状态：已确认
- 交付物：可侧载安装的 Android APK
- 首版平台：Android 11（API 30）及以上

## 1. 产品概述

墨笺是一款面向手机复习场景的本地 Markdown 阅读、编辑与资料管理应用。它接收来自微信、系统文件管理器和 App 内文件选择器的 Markdown 文件，将导入内容复制到用户可见的公共资料库，并提供完整的离线编辑与渲染体验。

首版只完成 Markdown 能力。架构为未来的 Obsidian 风格扩展和 Word、Excel、PDF 打开与格式转换保留边界，但不实现这些功能。

## 2. 目标与非目标

### 2.1 目标

1. 从微信选择“用其他应用打开”或“分享”后，直接把 `.md` 或 `.markdown` 文件导入墨笺。
2. 从 App 内导入单个文件、多个文件或完整目录，也可新建 Markdown 和目录。
3. 在公共目录 `Documents/MoNote/` 中按真实子目录管理资料，支持搜索、最近、收藏和标签。
4. 支持竖屏编辑/预览切换、横屏编辑/预览双栏以及方向锁定。
5. 完整渲染 GFM、公式、Mermaid、脚注、目录、本地图片和代码高亮。
6. 通过自动保存、撤销/重做、恢复草稿和外部修改冲突处理保护资料。
7. 完全离线运行；Android Manifest 不声明 `INTERNET` 权限。
8. 交付可安装、由开发调试证书签名的 APK，供个人学习使用。

### 2.2 非目标

首版不实现：

- Obsidian Wiki Link、双链图谱、Callout 或第三方插件；
- 云同步、账号、协作或网络内容抓取；
- PDF、Word、Excel 的打开、编辑或相互转换；
- Google Play 上架、正式商店签名或 AAB 发布流程；
- iOS、桌面或 Web 版本；
- 富文本所见即所得编辑。

## 4. 技术路线

采用“原生 Android 外壳 + 离线 Web 文档表面”：

- Kotlin、Jetpack Compose：资料库、权限、设置、存储管理、导航和原生系统集成；
- 单一本地 WebView 文档表面：CodeMirror 6 编辑器和渲染预览；
- Markdown-it：基础 Markdown 和 GFM 解析；
- Markdown-it 插件：任务列表、脚注、目录等扩展；
- KaTeX：行内和块级 LaTeX 公式；
- Mermaid：流程图等图表；
- Highlight.js：围栏代码高亮；
- DOMPurify：内嵌 HTML 安全清洗；
- Room：文件索引、最近、收藏、标签和文件指纹；
- DataStore：主题、方向模式、自动保存等偏好。

WebView 通过 `AndroidView` 嵌入 Compose。单一文档表面在横竖屏之间只改变 CSS 布局，不重新加载编辑器，避免丢失光标、选择和撤销历史。

## 5. 架构与模块边界

### 5.1 UI 层

- `OnboardingScreen`：解释全文件访问权限、打开系统授权页和重试。
- `LibraryScreen`：最近、目录、收藏、标签、搜索和多选管理。
- `ImportSheet`：显示来源、文件名、目标目录、冲突处理和导入进度。
- `DocumentScreen`：标题、保存状态、撤销/重做、方向控制、编辑/预览文档表面。
- `TrashScreen`：恢复、永久删除和清空回收站。
- `StorageScreen`：正文、附件、回收站、恢复草稿、备份和缓存占用。
- `SettingsScreen`：主题、字号、自动保存和默认方向。

### 5.2 领域层

- `LibraryService`
  - 扫描和重建资料库；
  - 导入、创建、移动、重命名、复制、导出、分享和删除；
  - 更新物理目录、Room 索引和元数据镜像。
- `ImportCoordinator`
  - 统一处理 App 内文件选择、微信/其他 App Intent 和文件夹导入；
  - 校验来源、读取临时 URI、处理同名、清理失败副本。
- `DocumentSession`
  - 持有当前正文、基线指纹、脏状态、保存状态和撤销/重做栈；
  - 调度恢复草稿、自动保存、退出判断和外部冲突处理。
- `RenderBridge`
  - 在 Kotlin 与本地 Web 文档表面之间传输文档状态和事件；
  - 只允许固定消息类型和受信任本地域。
- `RecoveryService`
  - 写入、比较、恢复和清理恢复草稿与上一个有效版本。
- `StorageInspector`
  - 计算各目录占用并执行用户确认后的清理。

### 5.3 数据层

真实 Markdown、附件和物理子目录是内容的唯一事实来源。Room 不保存 Markdown 正文。

推荐目录：

```text
Documents/MoNote/
├── 收件箱/
├── <用户创建的目录>/
├── _MoNoteSystem/
│   ├── catalog.json
│   ├── recovery/
│   ├── backups/
│   └── trash/
└── <笔记同级或子目录中的 assets/>
```

- `_MoNoteSystem/catalog.json` 是收藏、标签和稳定文件 ID 的原子镜像，用于 Room 损坏后的恢复。
- `recovery/` 只保存尚未正常关闭的恢复草稿和元数据。
- `backups/` 每个文档最多保存一个上一个有效版本。
- `trash/` 保持被删除文件的相对目录结构和删除时间。
- 主内容和 `_MoNoteSystem/` 都对外可见；系统目录使用明确名称并附带说明文件，方便文件管理器和清理工具识别。App 的“存储管理”会列出其占用和打开路径。
- 内部 App 缓存只能保存可重建的渲染缓存，清除后不得丢失正文、标签或恢复草稿。

## 6. 文件入口与导入

### 6.1 App 内入口

“＋”操作单包含：

- 导入 Markdown；
- 导入文件夹；
- 新建笔记；
- 新建目录。

文件导入默认允许多选。导入文件夹保持原目录结构。单文件导入会检查正文引用的本地相对图片；能够读取的资源可随文件复制，缺失资源在结果页和预览中明确标注。

### 6.2 微信和其他 App

Manifest 注册：

- `ACTION_VIEW`
- `ACTION_EDIT`
- `ACTION_SEND`
- `ACTION_SEND_MULTIPLE`

接收 MIME：

- `text/markdown`
- `text/x-markdown`
- `text/plain`
- `application/octet-stream`

由于发送方可能提供错误或通用 MIME，`ImportCoordinator` 还必须检查显示文件名、扩展名和内容可读性。通用 MIME 仅在扩展名为 `.md` 或 `.markdown` 且内容能够作为文本解码时接受。

流程：

1. 用户在微信选择“用其他应用打开”或“分享”，然后选择墨笺。
2. 墨笺读取临时 `content://` URI 的显示名、大小和内容流。
3. 显示导入确认页，默认目标为 `收件箱`。
4. 主操作为“导入并打开”；次操作为“仅临时打开”。
5. 导入以临时文件写入，关闭并校验后再重命名为最终文件。
6. 同名默认自动追加序号；不静默覆盖。
7. 复制完成后才更新索引；失败或取消时清理不完整副本。

从微信单独接收的 Markdown 通常不包含相对图片。缺失图片必须显示原路径和占位提示，不得使整篇预览失败。

### 6.3 外部原地打开

用户可选择“仅临时打开”，直接读取外部文件。若 URI 具备写权限，则允许原地编辑；否则进入只读预览并提供“导入资料库”或“另存副本”。外部文件不自动混入资料库索引。

## 7. 资料库交互

首页提供：

- 最近打开；
- 真实目录树；
- 收藏；
- 标签筛选；
- 文件名和正文搜索；
- 排序与视图切换；
- 存储和设置入口。

文件或目录长按进入多选模式，支持：

- 收藏和取消收藏；
- 添加或移除标签；
- 移动；
- 重命名；
- 导出或分享；
- 删除。

移动、重命名和删除必须先计算所有受影响路径，禁止覆盖现有文件。跨目录移动失败时回滚已完成步骤或保留可恢复操作记录。

删除先移动到 `_MoNoteSystem/trash/`。回收站保留原相对路径和删除时间，默认 30 天后在 App 启动或存储维护时清理。永久删除和清空回收站必须二次确认。

## 8. 编辑与方向行为

### 8.1 原生工具栏

顶部包含：

- 返回；
- 文件名；
- `已保存 / 未保存 / 正在保存 / 只读 / 保存失败` 状态；
- 撤销；
- 重做；
- 更多菜单。

编辑快捷栏包含常用标题、粗体、斜体、删除线、列表、任务、引用、链接、图片、代码、表格、公式和 Mermaid 模板插入。

### 8.2 竖屏

- 默认显示“编辑 / 预览”分段控制；
- 切换不销毁另一个面板；
- 预览返回编辑时恢复光标和滚动位置。

### 8.3 横屏

- 左侧编辑，右侧预览；
- 分隔比例可拖动并记住；
- 以源代码行号和渲染元素标记进行近似同步滚动；
- 用户主动滚动某侧时，短暂暂停自动跟随，避免拉扯。

### 8.4 方向控制

设置支持：

- 跟随系统；
- 锁定竖屏；
- 锁定横屏。

方向改变不得重新读取文件、清空撤销栈或丢失未保存内容。文档会话由 ViewModel 持有，Web 文档表面不因普通方向变化重建。

## 9. 保存、撤销与恢复

### 9.1 撤销与重做

- 连续键入按时间和操作类型合并，不逐字符形成历史。
- 自动保存不清空撤销/重做栈。
- 保存后执行撤销会形成新的脏状态，并再次进入自动保存。
- 单一文档会话最多保留 500 个步骤，同时受 20 MB 历史内存预算限制；先达到任一上限即淘汰最旧步骤。
- 关闭文档后不永久保存完整撤销栈。

### 9.2 自动保存

默认时序：

1. 输入立即更新内存正文和编辑器状态。
2. 停止输入约 500 ms 后更新恢复草稿。
3. 停止输入约 1 秒后尝试保存原文件。
4. 写入同目录临时文件，关闭并校验后替换目标文件。
5. 保存成功后更新基线指纹和状态。

应用进入后台时必须先尝试刷新恢复草稿，再尽力完成原文件保存。自动保存可在设置中关闭；关闭后仍维护恢复草稿。

### 9.3 退出

- 自动保存已完成且无脏状态：直接退出。
- 自动保存尚未完成、已关闭或保存失败：询问“保存 / 放弃 / 取消”。
- “放弃”只丢弃本次未保存变化；如果存在冲突或恢复草稿，需再次说明影响。

### 9.4 异常恢复

恢复草稿包含稳定文件 ID、原路径、基线哈希、草稿哈希和时间。正常保存并关闭后删除对应恢复草稿。

启动或再次打开文档时，如果草稿比原文件新且内容不同，显示：

- 恢复草稿；
- 查看差异；
- 丢弃草稿。

当无法安全写入恢复目录时，界面必须持续显示高优先级警告，并提供“复制全文”与“另存副本”。

### 9.5 外部修改冲突

打开文件时记录修改时间、大小和内容哈希。每次替换原文件前重新检查。若外部版本已经改变：

1. 暂停自动保存；
2. 保留当前内存内容和恢复草稿；
3. 提供“查看差异 / 保留我的版本 / 载入外部版本 / 另存副本”；
4. 任何覆盖动作都先保留上一个有效版本。

若当前文件被外部删除，禁止自动重新创建覆盖原路径，默认建议另存副本或恢复为新文件。

## 10. Markdown 能力

首版支持：

- CommonMark 基础块与行内语法；
- GFM 表格、任务列表、删除线和自动链接；
- 围栏代码块与语法高亮；
- 行内 `$...$` 和块级 `$$...$$` KaTeX；
- `mermaid` 围栏代码块；
- 脚注；
- 文档目录和标题大纲；
- 本地图片、相对链接和普通链接；
- UTF-8、UTF-8 BOM 和 UTF-16 文本。

不支持的编码进入只读诊断页，允许选择编码后重新打开或转换为 UTF-8 副本。

### 10.1 图片

从相册或文件选择器插入图片时：

1. 复制到当前笔记目录旁的 `assets/`；
2. 清洗文件名并避免覆盖；
3. 插入相对 Markdown 链接。

移动单个 Markdown 时，如果其引用的资源位于同一笔记目录内，移动操作提示是否同时移动相关资源。导入完整目录时保持所有相对路径。

## 11. WebView 安全

1. Manifest 不声明 `INTERNET` 权限。
2. HTML、JavaScript、CSS、字体、KaTeX、Mermaid 和高亮资源全部随 APK 打包。
3. 使用本地受信任虚拟源加载文档表面，不直接启用任意 `file://` 访问。
4. Kotlin 与 Web 层使用带受信任源限制的消息通道；不暴露通用反射式 JavaScript 接口。
5. 内嵌 HTML 经过 DOMPurify 白名单清洗，移除脚本、事件属性、iframe、危险 URL 和活动内容。
6. KaTeX 使用非信任模式；Mermaid 使用严格安全级别。
7. 本地资源映射先规范化和校验路径，只允许读取当前资料库或临时获准 URI 的资源，阻止 `..` 路径穿越。
8. 外部 HTTP(S) 链接不在 WebView 内加载；经用户操作后交给系统浏览器。
9. 远程图片不加载，只显示链接占位。

## 12. 性能策略

- 编辑输入必须即时更新；预览在停止输入约 250 ms 后更新。
- 新渲染请求到达时取消或丢弃过期结果。
- 目标：1 MB 普通 Markdown 在中端 Android 设备上 500 ms 内完成预览更新。
- Mermaid、长代码块和图片按可见区域延迟渲染。
- 超过 2 MB 自动降低实时预览频率。
- 超过 5 MB 默认切换为“手动刷新预览”，用户可恢复实时模式。
- 索引扫描在后台调度，界面先显示已有索引并增量更新。
- 搜索不得在主线程读取全部正文。

性能数值是验收目标，不保证所有 Mermaid 图表或低端设备都达到；超时必须降级而不是阻塞编辑。

## 13. 错误处理

| 情况 | 行为 |
| --- | --- |
| 全文件权限被拒绝或撤销 | 停止扫描和写入，不删除资料；提供重新授权和临时只读打开 |
| 微信临时 URI 无法读取或中途断流 | 不报告成功，清理临时副本；提供重试或先保存到下载目录 |
| 同名文件 | 默认追加序号；覆盖必须明确确认 |
| 存储不足 | 暂停保存，保留内存内容；优先保留已有恢复草稿并提供复制全文或另存 |
| 文件只读 | 允许预览；提供导入资料库或另存副本 |
| 单个 Mermaid、公式或代码块失败 | 只在该块显示错误；编辑器和其余预览继续工作 |
| 外部修改或删除 | 暂停覆盖；保留草稿并进入冲突流程 |
| Room 损坏 | 从真实目录和 `_MoNoteSystem/catalog.json` 重建 |
| 单个索引任务失败 | 记录本地诊断并继续扫描其他文件 |

诊断日志只在本机滚动保存，不记录 Markdown 正文。用户可从设置导出日志；App 不上传数据。

- `ACTION_VIEW`、`ACTION_EDIT`、`ACTION_SEND` 和 `ACTION_SEND_MULTIPLE`；
- 临时可读 URI；
- 错误 MIME、通用 MIME、无扩展名；
- 大小未知、读取中断和权限过期；
- 同名、空文件和非文本伪装文件。

最终在用户真机安装 APK，并用微信中的真实 Markdown 文件手动验证一次“用墨笺打开”。

## 15. 首版验收标准

1. 可构建并安装调试签名 APK。
2. 首次启动能解释并请求“访问所有文件”权限。
3. `Documents/MoNote/` 和其子目录可被外部文件管理器查看。
4. App 内能导入、新建、重命名、移动、搜索、收藏、加标签、导出、分享和删除 Markdown。
5. 微信中的 Markdown 可通过“用墨笺打开”进入“导入并打开”流程。
6. 竖屏采用编辑/预览切换，横屏采用双栏，三种方向控制生效。
7. GFM、KaTeX、Mermaid、脚注、目录、代码高亮和本地图片通过固定语料测试。
8. 自动保存、撤销/重做、退出确认和异常恢复通过测试。
9. 外部修改不被静默覆盖。
10. 回收站、草稿、备份和缓存占用可查看和清理。
11. Manifest 不包含 `INTERNET` 权限。
12. 恶意 Markdown 无法执行脚本或读取资料库外路径。
13. 旋转、后台杀进程、写入失败和索引重建不会丢失最后可恢复内容。

## 16. 扩展边界

后续功能通过稳定接口接入：

- `DocumentProvider`：为 PDF、Word、Excel 等定义打开、能力查询和导出接口；
- `RendererPlugin`：为 Wiki Link、Callout、Obsidian front matter 和其他 Markdown 扩展注册解析与渲染；
- `ConversionService`：将 Markdown/PDF/Office 转换作为独立任务，不耦合编辑会话；
- `LibraryLocation`：未来支持用户授权的外部资料库或云端缓存；
- `SyncProvider`：未来同步只处理版本和冲突，不改变正文存储契约。

首版只提供接口边界，不包含空入口、占位按钮或不可用菜单。
